# 架构与服务清单

## 硬件/系统

| 项 | 值 |
|---|---|
| 主机 | 群晖 NAS（x86_64，DSM 7.2.2） |
| 容器数 | 11 常驻 |
| SDR 主机 | 独立小主机，RTL-SDR × 2，WebSDR 服务 |
| 公网出口 | 云主机 frps（TCP 7000 控制 / 7001 UDP） |

## 常驻服务（脱敏命名）

| 服务 | 用途 | 端口（内网） | 公网暴露 |
|---|---|---|---|
| nginx 反代 | 统一 443 入口、TLS 终止 | 443 | 是（经 frp） |
| wavelog | 业余无线电日志（Web） | 80 | 是（路径反代） |
| Home Assistant | 智能家居控制 | 8123 | 否（仅内网/VPN） |
| snipe-it | 资产台账（MySQL 8 后端） | 8087 | 否 |
| camofox | 无头浏览器服务 | 9377 | 否 |
| mcsm | Minecraft 管理面板 | 23333 | 否 |
| frpc | 隧道客户端 | — | 出口本身 |
| WebSDR | 远程 SDR 接收 | 8073 | 是 |

## 为什么这样分

- **能内网就不出网**：HA / 资产台账 / 面板全部只在内网，需要时走 VPN 或隧道临时开。
  原因不只是安全，还有成本：每个公网端口都是一次扫描面。
- **反代与业务分离**：DSM 自带的 Web Station 与容器反代不必混用，证书、限流、
  安全头统一在 nginx 一处配置，容器替换不影响对外契约。
- **状态集中、日志分散**：容器 `restart: unless-stopped` 保证宿主机重启后自恢复；
  但日志按服务分离，避免一个服务的刷屏埋掉另一个的线索。

## 端口冲突排查顺序

DSM 7 上 80/443/5000/5001 都被系统占用，容器映射前先确认：

```bash
/usr/local/bin/docker ps --format '{{.Names}}\t{{.Ports}}' | sort
sudo netstat -tlnp | awk '{print $4}' | sort -u
```
